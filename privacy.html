Privacy policy

This policy describes the owner-operated Colab Drive Transfer desktop workflow maintained by TUSKIJAY.

Data accessed and purpose

With the user's Google authorization, the workflow accesses selected Drive files and folders, their contents and metadata such as names, IDs, sizes, timestamps and checksums. It uses these data to upload documents, download results, organize user-authorized batches and verify transfer integrity. OAuth access and refresh tokens are used to authenticate these operations.

Permission scope

The workflow requests https://www.googleapis.com/auth/drive because it needs to transfer existing files and results created by other tools, not only files created by this OAuth application. The granted scope can technically permit reading, creating, modifying and deleting Drive files. The workflow performs operations only within the user's requested scope; it does not automatically publish files or change sharing.

Storage and processing

Documents and results remain on user-controlled computers and in Google Drive. If the user requests conversion, selected documents are copied to a Google Colab runtime and processed there. Google operates Drive, OAuth and Colab under its applicable terms and privacy policy. This is cloud processing, not local offline processing.

OAuth credentials and tokens are stored in access-restricted configuration files on the user's computers. Transfer records may contain file names, paths, IDs, sizes, hashes, timestamps and error messages. Credentials and tokens are excluded from project logs and public pages.

Sharing and limited use

The workflow does not sell Google user data or use it for advertising, credit decisions or training general-purpose AI models. It does not send document contents to a separate model-inference API as part of file transfer. Any additional processing or sharing requires the user's separate instruction and appropriate disclosure.

Colab Drive Transfer's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Human access to private documents is limited to what the user authorizes or what is required for security or applicable law.

Retention, deletion and revocation

The user controls retention of original files, staging copies, results, logs and local credential backups. They remain until the user removes them; revoking Google access does not delete existing copies. To stop future access, revoke this application's connection in Google Account connections and remove its local credentials. To delete data, remove the relevant copies from the user's computers and Google Drive, including Drive Trash as appropriate.

This information website

These static pages contain no document-upload form, advertising or application analytics scripts. The website host, GitHub Pages, may process ordinary request information under GitHub's privacy statement. The website does not receive the desktop workflow's documents or OAuth tokens.

Contact and changes

Contact the maintainer through the project support page. Do not submit private documents, tokens or secrets in public issues. Material changes to data use will be disclosed and renewed consent obtained where required.
